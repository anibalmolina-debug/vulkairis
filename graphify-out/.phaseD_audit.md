## 1. Frozen @Overwrite signatures — HELD

`client/mixin/iris/SodiumProgramsMixin.java:27-52`, `@Mixin(SodiumPrograms)`:

- `createGlShaders(...)` → `Collections.emptyMap()`. No GL shaders. No draw.

## 2. @Inject door decision — DECISION-ONLY (no draw)

`client/mixin/iris/SodiumTerrainDoorMixin.java:51-101`:

- `getProgram` HEAD, cancellable, `require=0` — but **never calls
  `cir.setReturnValue`**. Falls through in all cases; the GL path returns
  `null` via the frozen overwrite. The "cancellable" is future-proofing only.
- Pack path (`decision.usePackPipeline()`): `StageDiagnostics.pass` + controller
  label writes only. Comment (L77) is explicit: "The Vulkan bridge owns the
  draw" — but nothing here binds a pipeline or issues a draw.
- Fallback path: `StageDiagnostics.warn` + `controller.setLastLinkError`
  only when `isPackActive()` (IrisBridge pack name check, L119-127).
- `getFramebuffer` RETURN: relabels `controller.setCurrentTarget(targetFor(...))`.
  Diagnostic label swap, not a target bind.
- Pass mapping (`simplePassName`, L103-116) distinguishes **only**
  TRANSLUCENT vs TERRAIN via `pass.isTranslucent()`. `TERRAIN_CUTOUT` and all
  three `SHADOW_*` door passes are unreachable through this mixin.

`TerrainPipelineDoor` (`vulkan/pipeline/TerrainPipelineDoor.java:21-226`) is
pure/device-free: `forPassName`, `programNameFor` (gbuffers_terrain /
gbuffers_terrain_cutout / gbuffers_translucent / shadow*), `targetFor`
(shadow→`shadowtex0`, else `colortex0`), `decideCompile` (linked id>0 → pack,
else fallback naming missing pipeline), `checkDescriptorSwap` /
`decideRender` (reflection+descriptor validation), `fallbackReason`
(requested/effective/stage/pack+shader/cause). **The mixin calls
`decideCompile` only** (L62-67); `decideRender`/`checkDescriptorSwap` have no
runtime caller — the descriptor-swap gate is specified but not executed.

## 3. Critical gap: door can never take the pack path at runtime

`VulkanModProgramBridge.java:565-617`: `noteTerrainProgram` /
`terrainLinkedId` / `terrainCompileDecision` / `clearTerrainRegistrations`.

- Grep over `src/` shows **zero production callers of `noteTerrainProgram`**
  (only `PhaseDTerrainDoorTest.java:179-191`). `link()` never registers its
  result in `TERRAIN_PROGRAM_IDS`.
- Hence `terrainLinkedId(...)` is always 0 at runtime → `decideCompile` always
  returns fallback. The pack branch of the door is dead until `link()` (or the
  terrain link site) wires registration.
- `terrainCompileDecision` wrapper is likewise test-only at runtime.

## 4. Vertex format / mesh extend — specified, not plumbed

`vulkan/pipeline/TerrainVertexContract.java:33-158`: 20 B base preserved +
5 fixed extensions (BLOCK_ID 4, MID_TEX_COORD 8, MID_BLOCK 12, TANGENT_FRAME 16,
TINT_AND_AO 8; extended stride 68 B), offsets, `inputLocations`, `validate`,
idempotent `settle(owner)`.

- Real settle: `IrisRenderSystemMixin.java:137`
  (`settle("IrisRenderSystem.initRenderer")`). Diagnostics-only re-settle
  attempt in `GlShaderMixin.java:48-53` (no-op after first settle, by design).
- Gap: the contract is pure Java metadata. No evidence of Sodium vertex-buffer
  stride change, `ChunkVertexType` extension, or `VkVertexInput*` wiring
  consuming it. `VulkanModProgramBridge.link()` (L167-186) picks from the
  `DefaultVertexFormat` candidate table (`BLOCK` = Position/Color/UV0/UV2/
  Normal) and **fails the link when inputs are uncovered** — the extended
  attributes are not consulted. Mesh extend per §6.2 is documented but not
  connected to the driver path.

## 5. colortex / shadowcolor targets — specs + validation, device-free

`bridge/TerrainTargets.java:29-256`:

- `create(w,h,colortexCount,shadowRes)`: colortex0..N `RGBA16F` screen-size,
  `depthtex0` `DEPTH32F` screen-size, `shadowtex0` `DEPTH32F` + `SHADOW_COMPARE`
  fixed square, `shadowcolor0` `RGBA8` fixed square, ping/pong `RGBA16F`,
  `final_output` `RGBA8`. Bounds: 1..16 colortex, power-of-two shadow res.
- `descriptors()`: `shadowtex0` LoadOp CLEAR with clear depth
  `SHADOW_CLEAR_DEPTH = 1.0f` (forward-Z). `shadowcolor0` color `RGBA8`.
- `validate()`: format (color-vs-depth), dimension (colortex == screen,
  shadow == square res), binding (`SHADOW_COMPARE`), lifetime (`needsClear`
  → first-clear-required). `FramebufferValidator` covers attachment presence
  only (no dimension/format cross-check — lives at registry/spec level).
- `resize()` skips `fixedTargets()` (`shadowtex0`, `shadowcolor0`).
- `PackChainPlan.targetPlan` (`rendering/exec/PackChainPlan.java:429-463`)
  mirrors the same set via `RenderTargetRegistry.standard`, with a literal
  fallback. `RenderTargetRegistry` constants: `SCENE_COLOR=colortex0`,
  `SHADOW_COLOR=shadowcolor0`.

## 7. One-frame-late shadow — documented, not "fixed"

- `bridge/ShadowFrameLag.java:18-77`: `publish(N)` / `sampleFor(N+1)` strict
  (`frameIndex != publishedFrame+1` → empty); `hasShadowFor`,
  `invalidate()` (reload/dimension), `describe()` states the rule.
- Referenced by: `SodiumTerrainDoorMixin` javadoc (L37-38), `TerrainTargets`
  javadoc (L25-27, allocation-only, never same-frames), `ShadowCulling`
  javadoc ("cull against the current frame's volume, sample the previous

- `rendering/exec/ShadowRenderer.java:16-84`: state/resource owner

- `vulkan/pipeline/ShadowCulling.java:12-67`: distance cull, shadow-pass

## 10. Phase D verdict — door skeleton complete, not yet drawing

To make the door actually draw (§6 goal), the missing links in order:

1. Register terrain links: call `noteTerrainProgram` from the terrain
   link path (else finding §3 keeps the pack branch dead).
2. Execute the render-path swap: invoke `decideRender`/`checkDescriptorSwap`
   where the handed pass is replaced (else descriptors never gate).
3. Plumb `TerrainVertexContract` stride/offsets into the real vertex input
   path, or record why `DefaultVertexFormat.BLOCK` suffices (else §6.2
   unverified in-game).
4. Extend `simplePassName` (or its successor) beyond the translucent boolean
   so CUTOUT/SHADOW door passes are reachable.
5. Reconcile §6.5 wording with §8: pack pass/target per-frame evidence is in
   `VulkairisController`/`StageDiagnostics`, not `RenderStateTracker`.

Tests present (device-free): `PhaseDTerrainDoorTest` — vertex layout, settle,
compile/render decisions, terrain bridge registration, targets/validation,
shadow lag/culling, fallback reasons.
