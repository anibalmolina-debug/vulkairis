## Gaps / observations (no action taken)

- **Gap 1 (only real gap vs §5.3/§5.6): `ShaderWarmup` is dead code in production.**
  Nothing calls `requestWarmup()` after `IrisBridge.onPipelinePrepared`; second-load
  warmth currently comes from disk cache only, not ahead-of-draw compile. Suggested
  wiring (Phase C follow-up): one `ShaderWarmup.requestWarmup()` after catalog discovery
  in `IrisBridge` — already non-blocking/worker-bound/generation-gated, so safe from the
  hook thread; progress surfaces via existing listeners + Compatibility tools.
- **Obs 2:** 4-arg translation key (expanded+program+defines) is defined + tested but has
  zero production users; `preprocessGlsl` uses the 2-arg key (`ShaderTranslator.java:186`).
  Sound today (translation is pure over expanded+stage; defines inject at compile time),
  ready for Phase B union work. No change needed.
- **Obs 3:** warmup compiles the `nodefines` key only; any future draw-path compile with
  defines keys separately — warmup entry set must then include active define sets.
- **Obs 4 (cosmetic):** disk write cap (512 KiB) vs memory/re-admit cap (256 KiB) is a dead
  band — `store()` rejects >256 KiB before persist. Harmless; align constants for clarity.
- **Acceptance:** "no stack OOM" holds by construction (malloc handoff + size gate +
  OOM/SOF containment); "second load cache-hot" holds via disk persistence (proven by
  round-trip test); in-game warmup-before-draw proof blocked on Gap 1 wiring.
